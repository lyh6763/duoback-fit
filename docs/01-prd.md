## 1. 개요

### 목적
기존 프로젝트는 "일반 쇼핑몰 UI를 React로 옮긴 것"에 머물렀다. 리뉴얼에서는 두 가지를 보여주는 것을 목표로 한다.

- **기획·UX 역량:** 의자를 고를 때 사용자가 실제로 겪는 문제(스펙 숫자를 내 몸에 대입하지 못함)를 정의하고, 이를 푸는 핵심 기능을 설계한다.
- **프론트엔드 역량:** Next.js App Router, TypeScript, 정적 생성(SSG), SEO, 타입이 있는 데이터 모델, 테스트로 "실서비스에 가까운 구조"를 보여준다.

### 핵심 문제
> "좌판 높이 450~550mm, 4D 팔걸이, 최대 하중 120kg"
> 사용자는 이 숫자가 **내 몸에 맞는지** 판단할 수 없다.

- 스펙은 의자 기준으로 쓰여 있고, 사용자는 몸 기준으로 생각한다.
- 비슷한 가격대 모델의 차이를 한눈에 비교하기 어렵다.
- 결국 "매장에 가서 앉아봐야 안다"로 끝나지만, 어느 매장에 어떤 모델이 있는지도 알기 어렵다.

### 핵심 가치
**"내 몸 기준으로 의자를 고른다."**
몸 정보 → 맞는 모델 추천(이유 설명 포함) → 비교 → 매장에서 직접 앉아보기까지 하나의 흐름으로 잇는다.

### 타깃 사용자

| 페르소나 | 상황 | 니즈 |
|---|---|---|
| **P1. 재택·사무 직장인** (28~40세) | 하루 8시간 이상 앉음. 허리·목이 불편해 처음으로 비싼 의자를 고민 중 | 스펙 용어를 몰라도 나에게 맞는 모델을 알고 싶음. 이유가 납득돼야 구매함 |
| **P2. 자녀 의자를 고르는 부모** (38~48세) | 초·중학생 자녀의 학습 의자 구매 | 아이 키에 맞는지, 몇 년 쓸 수 있는지 궁금함 |

## 2. 기능 범위

### In Scope
- **Fit Finder:** 6개 질문 → 권장 좌판 높이 계산 → 모델별 적합도와 추천 이유
- **의자 탐색:** 목록, 필터("내 키에 맞는 의자만" 포함), 정렬
- **의자 상세:** 색상·각도별 갤러리, 몸 기준 스펙 표기, 나와의 적합도
- **비교:** 최대 3개 모델 나란히 비교, 차이 항목 강조, URL 공유
- **매장 안내:** 매장별 전시 모델, 모델 기준 매장 필터
- **Fit 기준 안내:** 계산 방식 공개(신뢰성)
- **SEO:** 상품 페이지 정적 생성, 메타데이터, OG 이미지, 구조화 데이터, sitemap

### Out of Scope (이번 버전 제외)
- 장바구니, 결제, 주문
- 회원가입, 로그인, 리뷰 작성
- 실제 백엔드와 관리자 페이지 (데이터는 코드 내 정적 데이터)
- 실제 지도 API 연동 (정적 지도 이미지 또는 주소 텍스트로 대체)

## 3. 기능 정의

### F1. Fit Finder (핵심 기능)

- **개요:** 몇 가지 질문으로 몸 정보와 사용 패턴을 받아, 모델별 적합도와 이유를 보여준다.
- **트리거:** 홈 히어로 CTA, GNB의 "내 의자 찾기", 목록·상세의 Fit 배너를 클릭할 때
- **질문 (6단계, 목표 소요 시간 60초 이내)**

| 단계 | 질문 | 입력 형식 | 값 |
|---|---|---|---|
| 1 | 누가 앉나요? | 단일 선택 카드 | 나 / 자녀(학생) |
| 2 | 키와 체중을 알려주세요 | 슬라이더 2개 + 실루엣 미리보기 | 키 120~200cm(1cm 단위), 체중 25~150kg |
| 3 | 하루에 얼마나 앉아 있나요? | 단일 선택 | 3시간 미만 / 3~6시간 / 6~9시간 / 9시간 이상 |
| 4 | 주로 무엇을 하나요? | 단일 선택 | 업무(PC) / 학습 / 게임·여가 |
| 5 | 불편한 곳이 있나요? | 복수 선택 | 허리 / 목·어깨 / 엉덩이·허벅지 / 더위·땀 / 없음 |
| 6 | 예산은 어느 정도인가요? | 단일 선택 | ~60만 원 / ~80만 원 / ~100만 원 / 상관없음 |

- **동작: 매칭 계산** (순수 함수 `scoreChair(profile, chair)`, 단위 테스트 대상)

  1. **권장 좌판 높이(mm)** = 키(cm) × 2.5 + 25
     - 오금 높이 ≈ 키의 약 25%, 신발 보정 25mm를 더한 **단순화한 근사식**이다.
     - 실서비스라면 KS 인체치수 데이터 기반으로 보정해야 하며, F6 Fit 기준 안내 페이지에 이 한계를 명시한다.
     - 예시: 160cm → 425mm, 172cm → 455mm, 185cm → 488mm
  2. **제외 조건:** 체중이 최대 하중을 넘는 모델은 결과에서 제외한다.
  3. **점수 (100점 만점)**

     | 항목 | 배점 | 규칙 |
     |---|---|---|
     | 체형 적합 | 40 | 권장 좌판 높이가 조절 범위 **±15mm(허용 오차)** 안이면 40점. 그 밖이면 좌판이 높을 때(발받침으로 보정 가능) 1mm당 −0.5점, 좌판이 낮을 때 1mm당 −1점. 체중이 최대 하중의 85%를 넘으면 −5점. *(v0.2: 구현 중 고정형 의자가 1~2cm 차이로 크게 감점되는 문제를 발견해 허용 오차를 추가하고 감점 폭을 절반으로 줄였다)* |
     | 사용 패턴 | 25 | 6시간 이상: 4D 팔걸이, 메쉬 등판, 헤드레스트에 가점. 자녀: 학생용 카테고리에 가점, 조절 상한 여유가 40mm 이상이면 "성장해도 오래 사용" 가점 |
     | 불편 부위 | 25 | 허리 → 요추 지지 조절, 목·어깨 → 헤드레스트와 3D 이상 팔걸이, 엉덩이·허벅지 → 좌판 깊이 조절, 더위 → 메쉬 좌판·등판 |
     | 예산 | 10 | 예산 안이면 10점. 초과하면 10만 원당 −5점(제외하지 않고 "예산 +N만 원" 라벨 표시) |

- **결과 화면 (F1-R)**
  - 1순위 모델 1개를 크게, 대안 2개를 작게 보여준다.
  - 모델마다 **적합도 점수**(100점 만점, 확률처럼 읽히지 않도록 % 표기 없음), **근거 체크리스트 최대 3개**(예: "✓ 좌판 높이 455 mm / 420–520"), **주의 사항**(예: "발받침 권장")을 함께 표시한다.
  - 1순위 모델은 **점수 구성**(체형 /40, 사용 패턴 /25, 불편 부위 /25, 예산 /10)을 막대로 공개해 추천 근거를 투명하게 보여준다.
  - 내 입력 요약: 권장 좌판 높이를 크게 보여주고, 입력값 수정이 가능하다.
  - 액션: 상세 보기 / 비교에 담기(상위 3개 한 번에 담기 포함) / 매장에서 앉아보기 / 다시 하기 / 결과 공유
- **성공 기준**
  - 6단계를 60초 안에 끝낼 수 있다(옵션은 모두 탭 한 번, 슬라이더는 기본값 제공).
  - 결과마다 "왜 이 모델인지"가 최소 1개 이상의 근거로 설명된다.
  - 같은 입력이면 항상 같은 결과가 나온다(결정적 계산, 단위 테스트로 보장).
- **예외 처리**
  - 모든 모델이 하중을 초과하면 "맞는 모델이 없음" 화면과 함께 매장 상담 CTA를 보여준다.
  - 권장 좌판 높이가 모든 모델 범위보다 낮으면(아동 등) 결과는 보여주되 "발받침 사용 권장" 안내를 상단에 고정한다.
  - 중간에 이탈하면 진행 상태를 `sessionStorage`에 보존하고, 다시 들어오면 "이어서 하기 / 처음부터"를 묻는다.
  - 브라우저 뒤로가기는 이전 질문으로 이동한다(단계를 URL `?step=`과 동기화).

### F2. Fit 프로필

- **개요:** 마지막 Fit 결과를 저장해 사이트 전체에서 "나와의 적합도"을 보여준다.
- **동작:** 프로필은 `localStorage`에만 저장한다(서버 전송 없음). 저장된 프로필이 있으면 목록·상세·비교에 적합도 배지가 나타난다.
- **개인정보:** 공유 URL에는 원값 대신 **구간 코드**만 담는다(키 5cm 단위, 체중 10kg 구간). 예: `/fit/result?p=s-170-60-69-w-u-lb-80`
- **예외 처리:** 프로필 삭제 버튼을 제공한다. 공유 링크로 들어온 경우 "내 결과로 저장할까요?"를 묻는다.

### F3. 의자 목록

- **필터:** 용도(사무용/학생용), 가격대, 팔걸이(고정·3D·4D), 헤드레스트 유무, **"내 키에 맞는 의자만"**(프로필이 있을 때만 노출)
- **정렬:** 추천순(프로필이 있으면 적합도순), 가격 낮은순/높은순, 최신순
- **카드 정보:** 대표 이미지, 색상 스와치(누르면 이미지 변경), 모델명, 가격, **권장 키 범위**(예: "키 158~198cm"), 적합도 배지(프로필이 있을 때), 비교 담기 토글
- **상태:** 필터와 정렬은 URL 쿼리와 동기화한다(공유와 뒤로가기 지원).
- **예외 처리:** 결과가 0개면 필터 초기화 CTA와 Fit Finder CTA를 보여준다.

### F4. 의자 상세 (SSG)

- **갤러리:** 모델별 색상 2종 × 각도 4종(앞·좌·우·뒤). 색상을 바꾸면 각도 썸네일 세트가 바뀐다.
- **몸 기준 스펙:** 숫자 스펙 옆에 사람 기준 해석을 붙인다.
  - 좌판 높이 420~520mm → "키 158~198cm에 적합"
  - 최대 하중 120kg → "체중 약 100kg까지 여유 있게"(최대 하중의 85%)
- **나와의 핏:** 프로필이 있으면 적합도와 이유를, 없으면 "내 몸에 맞는지 확인하기" CTA를 보여준다.
- **CTA:** 비교에 담기 / 이 모델 전시 매장 보기 / 구매 상담(매장 연락처로 연결)
- **SEO:** `generateStaticParams`, `generateMetadata`, 상품별 OG 이미지(`opengraph-image.tsx`), JSON-LD `Product`
- **예외 처리:** 존재하지 않는 slug는 `notFound()`로 404 페이지를 보여준다.

### F5. 비교

- **개요:** 최대 3개 모델을 나란히 놓고 차이를 강조한다.
- **트리거:** 카드·상세·결과의 "비교 담기" → 하단 비교 트레이에 담김 → "비교하기"
- **동작**
  - 비교 대상은 `localStorage`에 유지하고, 비교 페이지 URL은 `/compare?m=q1w,d3hs`로 공유할 수 있다.
  - 행 그룹: 기본(가격, 용도) / 체형(좌판 높이, 권장 키, 최대 하중) / 조절(팔걸이, 요추, 헤드레스트, 좌판 깊이, 틸팅) / 소재 / 크기
  - "차이 나는 항목만 보기" 토글을 제공한다. 항목별로 가장 유리한 값을 강조한다(예: 하중이 가장 큰 모델).
  - 프로필이 있으면 맨 위에 "나와의 적합도" 행을 추가한다.
- **예외 처리**
  - 4번째 모델을 담으면 토스트로 "최대 3개까지 비교할 수 있어요"를 띄우고 트레이를 강조한다.
  - 1개만 담긴 상태로 비교 페이지에 들어오면 빈 슬롯에 "모델 추가" 카드를 보여준다.
  - URL의 잘못된 id는 무시하고 유효한 모델만 표시한다.

### F6. 매장 안내 · Fit 기준 안내

- **매장:** 매장 카드(주소, 영업시간, 연락처, 전시 모델 썸네일). `?model=slug`로 들어오면 그 모델을 전시한 매장만 보여준다.
- **Fit 기준 안내:** 계산식, 배점, 한계("근사식이며 실제 착좌를 대체하지 않음")를 공개한다. 신뢰성 확보와 동시에, 포트폴리오에서 설계 의도를 설명하는 페이지 역할도 한다.

### F7. 공통

- GNB: 로고 / 의자 / 내 의자 찾기 / 비교(담긴 개수) / 매장
- 페이지 이동 시 스크롤을 맨 위로 이동한다(Next.js 기본 동작). 404 페이지와 키보드 포커스 관리를 기본으로 갖춘다(기존 프로젝트에서 발견한 문제를 반영).

## 4. 데이터 모델

기존 데이터는 스펙이 문자열(`'450~550mm'`)이라 계산에 쓸 수 없었다. 리뉴얼에서는 **타입이 있는 수치 스펙**으로 다시 설계한다.

```ts
type Chair = {
  slug: string                     // 'q1w'
  name: string                     // 'Q1W 메쉬'
  category: 'office' | 'student'
  price: number                    // 원
  releaseDate: string              // ISO
  summary: string
  colors: { name: string; hex: string; slug: string }[]
  spec: {
    seatHeightMm: { min: number; max: number }
    seatDepthAdjust: boolean
    backHeightMm: number
    sizeMm: { w: number; d: number; h: { min: number; max: number } }
    maxWeightKg: number
    armrest: 'fixed' | '2d' | '3d' | '4d'
    headrest: boolean
    lumbar: 'none' | 'fixed' | 'adjustable' | 'dualback'
    tilt: 'none' | 'basic' | 'synchro'
    backMaterial: 'mesh' | 'fabric'
    seatMaterial: 'mesh' | 'fabric' | 'foam'
    base: 'nylon' | 'aluminum' | 'cantilever' | 'sled'
    warrantyYears: number
  }
}

type Store = {
  id: string
  name: string
  address: string
  phone: string
  hours: string
  displayModels: string[]          // Chair.slug[]
}
```

- **이미지:** 기존 규칙 `images/chairs/{slug}-{colorSlug}-{angle}.jpg`(5모델 × 2색 × 4각도 = 40장)을 그대로 재사용한다.
- **스펙 재보정 (구현 반영, v0.2):** 기존 좌판 높이(450~570mm대)는 공식에 넣으면 키 172cm 이상만 범위에 들어가서 현실적인 값으로 조정했다. 구현 중 스튜디오 사진을 확인해 보니 **학생용 두 모델은 캔틸레버·썰매형 다리라 높이 조절이 없는 고정형**이었고, D2500G는 메쉬가 아닌 패브릭이었다. 데이터는 사진 기준으로 맞췄다.

  | 모델 | 기존 | 확정 | 권장 키 |
  |---|---|---|---|
  | Q1W 메쉬 | 450~550 | 420~520 | 158~198cm |
  | D3-HS 메쉬 | 460~560 | 425~525 | 160~200cm |
  | D2500G-DASW | 470~570 | 440~540 | 166~206cm |

## 5. 기술 요구사항

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | Next.js (App Router) + TypeScript | 정적 생성, 메타데이터 API, 파일 기반 라우팅 |
| 렌더링 | 상품, 매장, 안내 페이지는 SSG. Fit Finder와 비교는 Client Component | 상품 페이지는 검색 노출, 개인화 영역은 클라이언트 |
| 스타일 | Tailwind CSS v4(`@theme` 토큰) | Figma Variables와 코드 토큰을 1:1로 대응 |
| 상태 | `useSyncExternalStore` 기반 Web Storage 스토어 (v0.2: Zustand 대신) | 프로필·진행 중 답변 두 개뿐이라 라이브러리 없이 충분. 하이드레이션 전에는 `undefined`로 "아직 모름"을 구분 |
| 데이터 검증 | zod (v0.2: `zod/mini`) | 정적 데이터의 타입과 런타임 검증. 클래식 zod는 모든 로케일을 함께 번들해 브라우저 JS의 약 1/3을 차지했다 |
| 테스트 | Vitest(매칭 로직, 데이터), Playwright(Fit Finder → 결과 → 비교 E2E) | 핵심 로직의 결정성 보장 |
| 이미지 | `next/image` | 반응형 이미지, 지연 로딩 |
| 배포 | Vercel | Next.js 기능(OG 이미지, 이미지 최적화)을 제약 없이 사용 |
| CI | GitHub Actions: lint → typecheck → test → build | 기존 프로젝트의 "검증 없는 배포" 개선 |

**품질 목표 (Lighthouse, 모바일):** Performance 90 이상 / Accessibility 95 이상 / SEO 100
